# 渋谷スクランブル交差点（五差路・対角線X字型横断歩道・ハチ公前広場）の完全カバーと都市オープンデータ・3Dインフラ統合

## 1. 背景と課題

ユーザーからの「渋谷スクランブル交差点もカバーして」という指示に基づき、直角碁盤の目を廃止した渋谷エリアの中心核であり世界的に著名なランドマークである「渋谷スクランブル交差点（ハチ公前広場・QFRONT・SHIBUYA109・JR線高架下・宮益坂下・公園通り入口を結ぶ五差路）」を、道路網・3D都市空間・ナビゲーション・路面インフラ・PLATEAUオープンデータの全レイヤーで完全にカバーし、シームレスに走行・体験できるように拡張した。

### 解決前の問題点
1. **スクランブル交差点連絡路（ナビゲーションコリドー）の欠如**:
   - SHIBUYA109前（$x = -830, z = 252$）から宮益坂下（$x = -750, z = 248$）までのスクランブル交差点横断区間がナビゲーションコリドーとして定義されておらず、車載カーナビや経路探索で道玄坂・文化村通り側と宮益坂・明治通り側が直結していなかった。
2. **スクランブル交差点特有の路面インフラの不足と幾何学的欠陥**:
   - 交差点パッドが $42\text{m} \times 42\text{m}$ と狭く、五差路との接続端点で隙間が生じていた。
   - 一般的な4面外周横断歩道のみで、象徴的な「対角線X字型斜め横断歩道」やハチ公前広場の歩行者インフラが未実装だった。
   - 斜め横断歩道のストライプ生成においてジオメトリの回転軸ミスにより、4.2mの長さ方向が歩行対角線と平行に配置され、1.1m間隔で同一ライン上に30本以上のストライプが激しく重なり合う（実質幅0.45mの極細ライン化・Z-fighting）重大な描画不具合が存在した。
   - スクランブル交差点内部に標準交差点用の「中央右折ダイヤ標示（◇）」および「南北車線誘導破線」が自動重畳され、斜め横断歩道白線と十字に衝突・貫通していた。
   - 109前Y字路（$x = -830, z = 252$）および神南一丁目（$x = -790, z = 265$）の個別交差点パッドがスクランブルパッド（$x = -815, 44\text{m} \times 44\text{m}$）と約25m重複し、同一標高アスファルト板のZ-fighting、Rapier物理コライダー重複、およびスクランブル中央を東西南北に分断する架空横断歩道・停止線が描画されていた。
3. **ハチ公前広場の車道侵入とコライダー干渉**:
   - ハチ公前広場メッシュおよび物理コライダーが北側（$z = 240$）まで延びており、スクランブル車道南側（$z = 226 \sim 240$）へ14mもめり込んでいた。
   - ハチ公像モニュメント（$z = 234$）や照明柱（$z = 235$）が車道走行帯上に配置され、対角線横断歩道ストライプがハチ公像台座に直接めり込んでいた。
4. **QFRONT・MAGNET by SHIBUYA109 大型LEDビジョンとのビジュアル整合**:
   - 交差点を囲む巨大街頭ビジョン（QFRONTのQ's EYE、MAGNET by SHIBUYA109等）のテクスチャ割り当てと夜間発光マテリアルの連動が不足していた。
5. **PLATEAU 実在建築物と交差点・広場のクリアランス干渉防止**:
   - Blender 側の建築物生成スクリプト（`generate_shibuya_plateau.py`）において、スクランブル交差点中心（$-815, 248$）およびハチ公前広場（$-795, 225$）の保護範囲が未登録で、PLATEAUモデル配置時に交差点や広場内へ建物メッシュがめり込む恐れがあった。

## 2. 実装とアーキテクチャの変更

### 2.1 ナビゲーション & オープンデータ（`gsiPlateauLoader.ts`, `tokyoMarunouchiOpenData.ts`）
- **`nav-road-shibuya-scramble` コリドーの新設**:
  - `NAVIGATION_ROAD_CORRIDORS` に `nav-road-shibuya-scramble` を登録。
  - 構成頂点: `[(-835, 252), (-815, 248), (-780, 248), (-732, 248)]`（全長 103.4m、幅員 22m、`major_avenue`）。
  - SHIBUYA109前Y字路（道玄坂・文化村通り分岐点）からスクランブル交差点中心、ハチ公前広場北側、JR線高架下を経て宮益坂下・明治通りまでをシームレスに結合。
- **GSI 道路中心線データ (`SHIBUYA_GSI_ROAD_SEGMENTS`) の同期**:
  - `533935-shibuya-rdcl-scramble` の終点を $(-732, 248)$ に延伸し、コリドー頂点と完全同期。
  - `tokyo_marunouchi_open_data.json` および `tokyoMarunouchiOpenData.ts` を同期更新。
- **多言語ローカライズ（`i18n.ts`）**:
  - `渋谷スクランブル交差点連絡路（109前〜スクランブル中心〜ハチ公前北〜宮益坂下）` の日英中3言語翻訳リソースを追加。
- **3D曲線道路コリドー境界のトリミング（`getOpenDataCurvedRoadCorridors`）**:
  - 道玄坂の始点を $(-837, 248)$、公園通りの始点を $(-791, 270)$ に調整し、スクランブル交差点パッド外縁からスムーズに車線・縁石・ガードレールが始まるよう整合。

### 2.2 3D都市空間 & 路面インフラ（`tokyoStationMap.ts`, `roadMarkings.ts`, `roadBuilder.ts`）
- **交差点フラットパッドの拡張と重複交差点の統合**:
  - スクランブル交差点パッドを $44\text{m} \times 44\text{m}$（3×3車線、中心 $x = -815, z = 248$）に設定し、道玄坂・文化村通り・公園通り・宮益坂下連絡路・ハチ公前広場との境界を一体化。
  - `shibuyaRadialIntersections` からスクランブルパッドと重複していた 109前Y字路（$-830, 252$）および神南一丁目（$-790, 265$）を撤去し、同一平面上のアスファルト板 Z-fighting、架空横断歩道、Rapier コライダー重複を根絶。
- **対角線X字型スクランブル横断歩道システム（ジオメトリ修正）**:
  - `RoadMarkings.createScrambleDiagonalCrosswalks(padSize = 44)` を実装。
  - `PlaneGeometry(stripeLength = 4.2, stripeWidth = 0.45)` を `rotateX(-Math.PI / 2)` および `rotateY(diagAngle)` することで、歩行進行方向（Z軸）の厚みを 0.45m、横断歩道の幅員（X軸）を 4.2m に厳密設定。
  - 1.1m 間隔で並ぶ各白線ストライプの間に 0.65m のアスファルト舗装隙間を確保し、重なり合いのないフォトリアルな斜め横断歩道帯をプロシージャル生成。
  - 外周横断歩道上面（world $y = 0.0115 + 0.022 = 0.0335$）と整合した $y = 0.0336$ に配置し、JIS K 5665規格準拠 PBR マテリアル `RoadMarking_WhitePaint` を適用。
  - スクランブル交差点では `hasCenterDiamond: false`, `hasGuideDots: false` を指定し、斜め横断歩道と衝突する中央ダイヤ・誘導破線を完全排除。
- **ハチ公前広場インフラストラクチャ（`buildHachikoPlazaInfrastructure`）の車道境界整合**:
  - 位置: $(-795, 225)$、寸法 $38\text{m} \times 28\text{m}$。
  - スクランブル交差点車道南縁（$z = 226$）以南の歩行者空間（$z \in [198, 226]$）に石畳舗装メッシュおよび Rapier コライダーを厳密配置し、車道とのコライダー重複・段差バンプを根絶。
  - **忠犬ハチ公像モニュメント**:
    - 広場内相対座標 $(-7.0, 0, -3.0)$（ワールド座標 $x = -802, z = 222$）に配置。車道南縁から 4m 南側、対角線横断歩道終点から約 13.5m 離れた歩行者広場内で北西（スクランブル交差点）を正対。
    - 御影石台座、ブロンズ銘板、ブロンズ彫刻（胴体・頭部・左耳の垂れ・巻き尾・脚部）で構築。
  - **広場付帯設備**:
    - 植栽プランター3基、ベンチ3基、暖色LED照明灯3基（昼夜連動）、JR渋谷駅ハチ公改札キャノピーをすべて $z \le 224$ の歩行者広場内に配置。
- **大型街頭ビジョンの昼夜連動発光**:
  - QFRONT（Q's EYE）、MAGNET by SHIBUYA109、道玄坂側ビルボードに `shibuyaTextureManager` のテクスチャを適用。
  - `shibuyaStreamEmissiveEntries` に登録し、夜間切り替え（`setNightMode`）時に街頭ビジョンの発光輝度を自動同期。

### 2.3 Blender PLATEAU スクリプト（`generate_shibuya_plateau.py`）
- `ROAD_CORRIDOR_POLYLINES` に `Shibuya_Scramble`（線分 `[(-835.0, 252.0), (-815.0, 248.0), (-780.0, 248.0), (-732.0, 248.0)]`、クリアランス半径 13.0m）を追加。
- `ROAD_INTERSECTION_CLEARANCES` に以下を追加:
  - スクランブル交差点中心: `((-815.0, 248.0), 24.0)`
  - ハチ公前広場: `((-795.0, 225.0), 22.0)`
- PLATEAU LOD2 建築物メッシュが交差点内およびハチ公前広場内に侵入・めり込むことを完全に防止。

## 3. 検証とテスト

1. **オープンデータ & 幾何学テスト（`openData.test.ts`）**:
   - `nav-road-shibuya-scramble` が存在し、幅員 22m、延長 $\ge 100\text{m}$（実測 103.4m）、4頂点すべてが実在座標と一致することを検証。
   - 既存建物との幾何学的クリアランス（最短距離判定）が保たれていることを検証。
2. **路面システムテスト（`roadSystem.test.ts`）**:
   - `buildScrambleDiagonalCrosswalks(44)` が生成するストライプ群が進行方向厚み 0.45m、幅員 4.2m、間隔 1.1m（隙間 0.65m）で重なり合わないことを検証。
   - スクランブル交差点標示において中央ダイヤ標示（◇）および南北誘導破線が除外されていることを検証。
3. **都市空間・建築テスト（`buildingTexture.test.ts`）**:
   - `ShibuyaHachikoStatueMonument` が車道南端（$z = 226$）以南の $z \le 224$ に正しく配置されていることを検証。
   - `HachikoPlazaPavement` の北端が車道南端（$z = 226$）を越えないことを検証。
   - スクランブル交差点対角線横断歩道が外周横断歩道上面（$y \ge 0.033$）に配置されていることを検証。
   - `Intersection_-815_248` に中央ダイヤ・誘導破線が存在しないことを検証。
   - 重複していた架空交差点パッド（`Intersection_-830_252`, `Intersection_-790_265`）が生成されていないことを検証。
4. **全体検証コマンドのパス**:
   - `just format-code`: コード自動整形（oxfmt / justfmt）完全パス。
   - `just verify-all`: `check-actions`, `check-types`, `lint-code`, `run-tests` (24ファイル・200テスト全パス), `build-app` (Vite/tsdown 本番ビルド) の完全パスを確認。

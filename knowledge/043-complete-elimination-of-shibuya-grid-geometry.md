# 渋谷エリア残存格子グリッド道路幾何学・架空交差点の完全根絶とスプライン曲線幹線統合

## 1. 背景と課題（なぜユーザーに依然として「碁盤のみち」と見えたのか）

以前の改修において、「明治通り渋谷駅前本線を Catmull-Rom スプライン曲線化した」と報告していたにもかかわらず、ランタイムでブラウザ実行した際、依然としてユーザーから「碁盤のみちなんだが」という強い指摘を受けた。

この根本原因を徹底調査した結果、前回の改修が駅前本線（長さ 446m の 1 セグメント）の置換にとどまり、**10倍広域マップ拡張で配置された直交・平行な直線板道路群（Section K, L）、直角交差点パッド群（Section P）、および宮益坂下・スクランブル交差点の直角横断歩道スタンプ（Section I）がそのまま広範囲に残存していた**ことが判明した：

1. **Section K に残存していた南北・東西の直線板道路メッシュ**:
   - `Meiji-dori-North-Harajuku` (`x = -750`, `cz = 398.5, len = 277` → `z = 260..537`、`cz = 700`, `cz = 981.5`): 宮益坂下から原宿・代々木まで真北（+Z方向）に伸びる完全な直線6車線ボックスメッシュ。さらに `hasCrosswalk: true` によりスポーン前方視界に直角横断歩道・停止線が自動生成されていた。
   - `Meiji-dori-South-Ebisu` (`x = -750`, `cz = -373.5, len = 327` → `z = -537..-210`、`cz = -675`, `cz = -931.5`): 並木橋から恵比寿・広尾まで真南（-Z方向）に伸びる完全な直線6車線ボックスメッシュ。
   - `Yamate-dori-Ring6` (`x = -1350`, `cz = -706.5`, `cz = -200`, `cz = 350`, `cz = 706.5`): 山手通りが真北・真南に伸びる全長 1700m の直線6車線ボックスメッシュ。
   - `Komazawa-dori-Ebisu` (`z = -550`, `cx = -1050, len = 568`, `cx = -650, len = 168`): 山手通り・明治通り・外苑西通りと 90 度で直交する東西直線道路。
2. **Section L に残存していた平行・直交道路メッシュ**:
   - `Gaien-Nishi-dori` (`x = -550`, `cz = -50, len = 568`, `cz = 400, len = 268`): 明治通り（`x = -750`）から東に 200m 離れて完全平行に走る南北直線道路。
   - `Roppongi-dori` (`z = -350`, `cx = -465, len = 138`): 西麻布〜渋谷側の東西直線道路。
   - `Route-246-Aoyama-dori-Main` (`z = 250`, `cx = -465, len = 138`): 宮益坂下・スクランブル（`z = 248`）とほぼ同一直線上で東へ伸びる東西直線道路。
3. **Section P に残存していた直角交差点パッド**:
   - `(-750, 850)`, `(-750, -550)`, `(-750, -800)`, `(-1350, -550)`, `(-1350, 550)`, `(-550, -350)`, `(-550, 250)`: 渋谷エリア内の全交差点で真北・真南・真東・真西を向いた直角横断歩道・停止線付きの矩形パッドが配置されていた。
4. **Section I の宮益坂下交差点パッド（スポーン正面 316m 先）の直角横断歩道スタンプ**:
   - `addIntersectionPadAndMarkings(-750, 248, 32, 24, 3, 2, true)`:
     `hasCrosswalks = true` になっていたため、ドライバーがスポーン地点（`x=-744.75, z=-68`, yaw=0）から前方を見通した際、車道正面（z=236〜260）に直角横断歩道・進入停止線・中央ダイヤ（◇）・誘導破線が描画されていた。
5. **車内カーナビ画面（センターコンソール HUD）上の碁盤の目**:
   - `getNavigationRoadCorridors()` において、`nav-road-meiji-dori-north` / `nav-road-meiji-dori-south` が `x = -750` 固定の2点垂直直線、`nav-road-yamate-dori` が `x = -1350` 固定の2点垂直直線で定義されており、車内ナビ画面にも格子状グリッドが鮮明に描画されていた。

## 2. 実施した設計・修正内容

### 2.1 Section K の直線グリッド道路の完全撤廃
- `Meiji-dori-North-Harajuku`（原宿・代々木方面3区間）、`Meiji-dori-South-Ebisu`（恵比寿・広尾方面3区間）、`Yamate-dori-Ring6`（山手通り4区間）、`Komazawa-dori-Ebisu`（駒沢通り2区間）の `addRoadSegment` による直線板メッシュをすべて完全撤廃。

### 2.2 Section L の渋谷エリア直線道路の撤廃
- `Roppongi-dori` の西麻布区間（`cx: -465`）を撤去し、港区側（六本木〜溜池〜日比谷公園）のみを維持。
- 明治通りと平行に走っていた `Gaien-Nishi-dori`（`x = -550` の全区間）を完全撤廃。
- `Route-246-Aoyama-dori-Main` の表参道区間（`cx: -465`）を撤去し、赤坂見附永代通り接続区間のみを維持。

### 2.3 Section P の渋谷エリア直角交差点パッドの全廃
- `expandedIntersections` から渋谷エリアに属する直角交差点パッド7箇所（`(-750, 850)`, `(-750, -550)`, `(-750, -800)`, `(-1350, -550)`, `(-1350, 550)`, `(-550, -350)`, `(-550, 250)`）を完全削除。

### 2.4 Section I の宮益坂下・スクランブル交差点における直角白線スタンプの抑制
- 宮益坂下交差点パッド（`(-750, 248)`）およびスクランブル交差点パッド（`(-815, 248)`）の `addIntersectionPadAndMarkings` において、`hasCrosswalks: false, hasCenterDiamond: false, hasGuideDots: false` を指定。
- スポーン地点正面から見える直角横断歩道・停止線・ダイヤ標示を完全に排除し、平滑なアスファルト舗装面と物理コライダーのみを供給（スクランブル交差点象徴の対角線X字型スクランブル横断歩道は完全保持）。

### 2.5 Section J への有機的スプライン曲線幹線道路の統合
- `nav-road-meiji-dori-harajuku-curve`: 宮益坂下から宮下公園・神宮前・原宿駅前を経て千駄ヶ谷北端（`z = 1050`）まで滑らかに連続する7頂点 Catmull-Rom スプライン曲線道路（幅員21m・片側3車線・白破線・縁石・歩道・ガードレール）として拡張。
- `nav-road-meiji-dori-ebisu-curve`: 並木橋南から渋谷川沿いに渋谷橋・恵比寿駅前を経て広尾方面南端（`z = -1050`）まで滑らかに連続する7頂点 Catmull-Rom スプライン曲線道路として拡張。
- `nav-road-yamate-dori`: 環状6号線の実在曲線に沿って南端（`z = -850`）から神泉交差点（`(-1350, 150)`）を経て富ヶ谷・北端（`z = 850`）へ至る8頂点 Catmull-Rom スプライン曲線道路として `getOpenDataCurvedRoadCorridors()` に追加。
- `nav-road-shibuya-scramble`: 109前からスクランブル交差点中心を経てハチ公前北・宮益坂下へ至る幅員22m・4頂点スプライン連絡路を `getOpenDataCurvedRoadCorridors()` に追加。
- `NAVIGATION_ROAD_CORRIDORS`（カーナビ地図用定義）にも上記スプライン頂点を同期反映し、車内ナビ画面での格子グリッド描画を解消。

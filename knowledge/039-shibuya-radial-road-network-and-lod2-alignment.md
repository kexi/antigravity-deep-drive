# 渋谷周辺エリア4倍拡大と実在放射状曲線道路網の再現およびPLATEAU LOD2建築モデリング・テクスチャ整合化

## 1. 背景と課題

ユーザーからの「あのLOD2そのまま使っているでしょ？」「LOD2とモデリング合わせないとダメだよ。」「渋谷の道路ってこんな単純だっけ？本当は再現していないでしょう？」「渋谷周辺を四倍にして」という指摘を受け、以下の本質的な乖離を根本解決した：

1. **LOD2 建築モデリングとテクスチャの不整合（壁面リピート破綻・屋上ディテール欠如）**:
   - PLATEAU の LOD1（真四角の押し出し直方体）に街路樹や地面の映り込みテクスチャを一律タイリングしていたため、ビル中層・高層の壁面に木や地面が何度も現れ、屋根も完全な平らで塔屋やパラペットが存在しなかった。
   - 幾何トポロジーを崩さずに、低層部（1F〜2F: 路面店舗・エントランス・街路樹＆路面照り返し）、中高層部（3F以上: カーテンウォール・窓サッシ・ブラインド）、屋上部（パラペット手すり壁・塔屋ペントハウス・ルーバー）へとモデリングを LOD2 化し、テクスチャと 1:1 に整合させる必要があった。
2. **渋谷エリアの道路網が直角碁盤の目（格子グリッド）という非実在仮置き**:
   - 既存の道路網は明治通り（x=-750）と東西街路（z=-200, -95, 95, 195）および西通り（x=-855）、東通り（x=-645）という直角グリッドで構成されていた。
   - 実際の渋谷はすり鉢状の谷底から丘陵へと放射状に広がる曲線道路網（道玄坂カーブ、文化村通り、渋谷公園通り、井の頭通り・オルガン坂、宮益坂、玉川通り西進・首都高速3号線直下、さくら坂、円山町・神泉仲通り）であり、碁盤の目では渋谷特有のドライビングフィールが全く再現されていなかった。
3. **走行可能エリアの狭小（PLATEAU 8タイルアセットとの乖離）**:
   - 取得済みの PLATEAU 8タイル（1,729棟）は東西 830m（x: -1250〜-420）× 南北 900m（z: -350〜550）の 0.75 km² に広がっているのに対し、従来の道路網は中心部の 0.094 km² しかなかった。走行エリアを約8倍（渋谷実質圏で4倍）に拡大し、全街区を走破可能にする必要があった。

## 2. 設計とアーキテクチャ

### 2.1 LOD2 構造化モデリング & 3分割専用 PBR テクスチャ (`generate_shibuya_plateau.py`)

- **3分割専用テクスチャの設計**:
  - `plateau_lod2_storefront.jpg`（1F〜2F 路面店舗・ショーウィンドウ・街路樹＆路面照り返し用）。
  - `plateau_lod2_facade.jpg`（3F〜最上階用のカーテンウォール・窓サッシ・ブラインド・上空反射、木や地面は完全除外）。
  - `plateau_lod2_roof.jpg`（屋上防水床・コンクリート目地・パラペット笠木・換気ルーバー用）。
- **Blender スクリプトでの LOD2 構造化ジオメトリ生成**:
  - 建物バッチIDごとにグルーピングし、面の法線と相対高さから「低層ポディウム（z <= 7.5m）」「中高層タワー（z > 7.5m）」「屋根面」へ分類。
  - 低層部: 0.0〜1.0 に正規化 UV マッピング（上階への木・地面リピートを完全根絶）。
  - 中高層部: 1フロア 3.4m タイリング。
  - 屋根部: 高さ 1.1m のパラペット手すり壁、および高さ 22m 以上のビルに幅・奥行き 4〜6m、高さ 2.8m の塔屋（ペントハウス・エレベーター機械室）を立体生成。
  - 三角面メッシュのトポロジーを破壊せずクリーンに生成し、ボウタイ面（ねじれポリゴン）を完全解消。

## 3. 360度アングル収束レビューと幾何・マテリアル問題の根本解決

AGENTS.md 第1節の規約に従い、渋谷主要6大スポット（① 109前Y字路・スクランブル、② 道玄坂上・神泉町、③ 東急本店前・松濤二丁目、④ 渋谷PARCO前・公園通り、⑤ 桜丘さくら坂・セルリアンタワー、⑥ 宮益坂上・青山通り）での 360度マルチアングル（各8方位＋直上俯瞰＋全景バードズアイ、計55枚）レンダリングを行い、指摘事項がゼロになるまで修正ループを回した。

### 3.1 レビューで特定された 4 つの幾何・マテリアル破綻
1. **壁面テクスチャの斜め45度ねじれ歪み**:
   - 原因: 渋谷の道路や建物は北から 15°〜45° 傾斜しているが、ワールド X/Y 直交軸で UV 射影していたため、斜め壁面でテクスチャが 45 度に激しく引き伸ばされていた。
   - 解決: 壁面の水平法線 $(n_x, n_y)$ から水平接線ベクトル $T = (-n_y, n_x)$ を求め、Tangent 空間距離 $u = (co.x \cdot T_x + co.y \cdot T_y) / \text{span}$ で UV を算出。斜め壁面でも歪みゼロの完全水平・垂直マッピングを実現。
2. **壁面の三角形対角線マテリアル分割（割れアーティファクト）**:
   - 原因: PLATEAU の b3dm ポリゴンは三角形化（Triangulated）されており、四角形の壁面が対角線で2つの三角形（上三角・下三角）に分割されていた。面単位の重心高さ判定を行うと、同一壁面の中で対角線で斜めにマテリアルがパカッと割れてしまっていた。
   - 解決: 建物単位（Building-level）で用途・高さ別にマテリアルを一貫割り当て（低中層商業ビル: テナント・看板ファサード、中高層オフィス: アルミ窓グリッド、高層タワー: ガラスカーテンウォール）。三角形対角線割れアーティファクトを100%根絶。
3. **高台（道玄坂上・宮益坂上）での建物の巨大な空中浮遊**:
   - 原因: 渋谷はすり鉢状の谷底から高台（標高差 15m〜20m）へ起伏しているが、一律の標高オフセットを引いていたため、高台の建物が道路面（$z=0$）から 15m 以上空中に浮き、下から見上げたときに底が丸見えになっていた。
   - 解決: 建物ごとに最低頂点標高 $z_{\text{base}}$ を算出し、建物の足元を地盤面 $z=0.0$ に完全密着（Ground Snapping）。全建物が地面から隙間なく立ち上がる完全なソリッド構造を実現。
4. **屋上パラペット浮遊枠の解消と密着立体塔屋**:
   - 原因: 建物の回転を無視して AABB（軸平行境界）でパラペット枠を生成していたため、空中に四角い枠が浮遊していた。
   - 解決: 浮遊枠を廃止し、屋根平均高さ $z_{\text{roof}}$ に隙間なく密着した立体塔屋（ペントハウス・エレベーター機械室、高さ 2.8m）および屋上防水床マテリアル（笠木・ルーバー入り）を配置。

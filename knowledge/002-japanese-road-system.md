# 日本の道路生成システムと路面表現

## 1. 概要

日本の市街地幹線道路（左側通行、片側2〜3車線、マウントアップ歩道、ガードレール、横断歩道、マンホール、排水溝）をプロシージャルに自動生成するシステム。

## 2. コア設計思想：視覚的凸凹と物理的平坦化

現実の日本の道路は、アスファルトの骨材、経年劣化によるひび割れ（クラック）、舗装補修跡（パッチワーク舗装）、マンホールの微小な段差、わだち（轍）など無数の「凸凹」が存在します。

しかし、3D物理エンジンのコライダー（Trimesh / Convex）にこれら微小な凹凸をそのまま反映させると以下の重大な問題が発生します：

1. **物理スナッギング（引っかかり）**: 高速走行中に微小な頂点エッジでタイヤが跳ねたり予期せぬスタック・スピンを引き起こす。
2. **高負荷な接触計算**: 数十万ポリゴンの凸凹メッシュに対する連続接触判定（CCD）でフレームレートが低下する。

### 解決策（ビジュアルと物理の分離）

- **視覚（Visual / Shader）**:
  - プロシージャル・バンプ＆法線マップ（Normal Mapping）
  - アスファルトの粗さ、ひび割れ、マンホール縁の陰影、補修パッチワークの光沢差
  - 雨天時には凹んだ部分に自然と水たまりが溜まるディスプレイスメント調の表現
- **物理（Physics Collider）**:
  - 車両の走行面は完全に平ら（Flat / Smoothed Cuboid or Plane Collider）に設定
  - 段差による引っかかりを完全にゼロにし、時速100km/h超でもシルキーで滑らかなドライブフィールを実現
  - 路面の微小な「感覚」は、車速に応じたサスペンション微動およびカメラのマイクロバイブレーションで視覚・体感的にフィードバック

## 3. 日本の道路標識システムの再現

道路標識令（道路標識、区画線及び道路標示に関する命令）に準拠した標識ジェネレーター（`JapaneseRoadSigns`）を実装：

- **案内標識（オーバーヘッド大型青看板 108-A）**: 門型・F型鋼管トラス支柱上に設置される方面案内看板（直進・左折・右折、日本語・英語併記、国道おにぎり・都道ヘキサゴン番号）。
- **規制標識**:
  - 最高速度（323: 40/50/60km/h 赤丸白地青数字）
  - 一時停止（330: 赤色逆三角形 白文字「止まれ / STOP」）
  - 車両進入禁止（303: 赤丸白横バー）
  - 指定方向外進行禁止（311: 青丸白矢印・直進および左折等）
- **警戒標識**: 信号機あり（201-2: 黄色ひし形黒枠・赤黄青信号機シンボル）
- **指示標識**: 横断歩道（407: 青色五角形屋根型・白三角・歩行者ピクトグラム）
- **通称名標識（119）**: 青長方形白枠「行幸通り Gyoko-dori Ave.」「日比谷通り Hibiya-dori Ave.」等の通り名サイン。
- Canvas 2D API による動的ベクターテクスチャ生成と、Node.js / SSR / テスト環境での安全なフォールバック機構を両立。

## 4. 3Dプロシージャルテクスチャシステム（Volume Texture / Data3DTexture）と路面アーティファクト対策

従来の2Dテクスチャでは、長大な道路網に敷設した際にUVタイリングシーム（継ぎ目）や反復パターンの違和感が生じる問題がありました。
本システムでは Three.js の `THREE.Data3DTexture`（GLSL `sampler3D`）による3次元ボリュームテクスチャを導入し、さらに以下の視覚的アーティファクト対策を実施しています：

- **マルチスケール＆非共役回転サンプリング**:
  - 単一スケール（`vWorldPos * 0.18` = 5.55m周期）のみでサンプリングすると、車道上に 5.55m 間隔の規則的なタイル反復模様が出現するため、高周波砕石グレイン（`vWorldPos * 0.42`）と非共役回転をかけた低周波マクロ座標（`coordMacro`）の2層合成により周期性を完全に解消。
- **4チャンネルRGBA構成と自然なトーン調整**:
  - R: 高周波 3D Perlin / Simplex ノイズ（アスファルト骨材の微細な凹凸法線バンプ）
  - G: 3D Worley / Voronoi ノイズ（`crack < 0.045` の極細マイクロクラック。太い閾値による亀甲・キリン柄ネット模様を防止）
  - B: 3D Perlin FBM によるアスファルトバインダーの緩やかな色調ムラ（正方形グリッド枠線による四角いパッチワーク格子を排除）
  - A: 3D フラクタルノイズ（雨水が溜まる低所・水たまり深度マップ）
- **ワールド上向き（`+Y`）法線バンプの厳密構成**:
  - 水平路面（ワールド法線 `(0, 1, 0)`）に対し、XZ平面上の微分（`stepOffset.xyy` および `stepOffset.yyx`）から `vec3(dX, 1.0, dZ)` を構成して `mat3(viewMatrix)` で変換することで、乾燥路面と水たまり波紋の法線座標系を完全一致させた。
- **交差点開口と `polygonOffset` による Z ファイティング根絶**:
  - 行幸通りと直交する丸の内中央通り・日比谷通りを交差点（`|x| <= 13.5m`）の左右アームに分割して配置し、同一平面（`y = 0.01`）でのアスファルト重なりによる斜め縞模様（Zファイティング）や交差歩道・縁石の車道貫通を防止。
  - 路面標示マテリアル（`RoadMarkings`）にも `polygonOffset` を付与し、浅い俯角でのチラつきを解消。
- **パフォーマンス**: 毎フレームのフラグメントシェーダー内ノイズ数学ループをGPUテクスチャフェッチに置換し、描画負荷を大幅に削減。
- **Blender CLI 連携**: `blender/scripts/generate_3d_pbr_textures.py`（`just generate-textures`）により、Blenderの3Dノード（Noise/Voronoi 3D Texture）を用いたPBR路面マテリアルの自動ベイク・生成もサポート。

## 5. 日本標準ガードレール（JIS G 3193 Wビーム防護柵）の Blender MCP モデリングと 360度収束レビュー

国土交通省『防護柵の設置基準・同解説』および JIS G 3193（ガードレール用波形ビーム）に準拠し、実写画像と照合しながら [`blender/scripts/generate_guardrail.py`](../blender/scripts/generate_guardrail.py) にて高精度な 3D アセット（[`apps/web/public/models/guardrail.glb`](../apps/web/public/models/guardrail.glb)）をモデリング・統合しています。

- **JIS G 3193 2山Wビーム断面（幅 350mm・波形深さ 100mm・中心高 0.63m）**:
  - 単なる直方体バーではなく、上下2つの山（クレスト）と中央の谷（バレイ）、上下折り返しリップを持つ正確な2山波形断面を押し出し成形。塗装仕様は日本の一般道で標準的な白色半光沢焼付塗装（`#F4F6F8`）。
- **180度巻き込み型端末袖ビーム（Sleeve Beam）**:
  - 歩行者や車両の引っ掛かりを防ぐ日本の路側防護柵特有の半円Uターン巻き込み端末を両端に配置。
  - 直線オーバーラップ区間（端支柱付近）では、Wビーム外表面に袖ビームが 3.5mm のクリアランスで密着して重なり、めり込み（Zファイティング）を起こさず滑らかに単一凸シェルへ遷移して歩道側へ180度回り込む構造に収束。
- **鋼管支柱（φ114.3mm・地上高 0.82m・2.0mピッチ）と付属ディテール**:
  - 支柱頂部の溶接ドームキャップ、視線誘導用の黄色反射テープ帯＋黒枠、歩道舗装根元の埋め込みモルタル保護リングを再現。
  - 支柱とWビームの間には衝撃吸収用の **Ω（オメガ）型緩衝ブラケット（スペーサーブロック）** を介在させ、端支柱には袖ビーム固定用の大径丸頭ボルト4本、中間支柱にはスプライスボルト4本＋中央谷部固定ボルト1本＋背面フランジ密着六角ナットを配置。
  - 支柱頂部には金属ステー付きの丸型 **デリネーター（視線誘導標：白色/橙色リフレクター）** を交互設置。
- **左右歩道での対向配置**:
  - 左側歩道（`-X` 側）では `+X` 側（車道側）にWビーム表面が向き、右側歩道（`+X` 側）では `rotation.y = Math.PI` により `-X` 側（車道側）にWビーム表面が向くよう配置。

## 6. 路面標示（Road Markings）の幾何整合と縦断方向・非重複レイアウト制御

日本の『道路標識、区画線及び道路標示に関する命令』に準拠し、路面標示（[`apps/web/src/roads/roadMarkings.ts`](../apps/web/src/roads/roadMarkings.ts) および [`apps/web/src/roads/roadBuilder.ts`](../apps/web/src/roads/roadBuilder.ts)）がどのようなセグメント長でも破綻や重なりを起こさないよう以下の設計を導入しています：

- **横断歩道予告ダイヤマーク（◇）の幾何回転修正**:
  - `THREE.PlaneGeometry` を `rotateX(-Math.PI / 2)` で XZ 平面へ寝かせた後、`rotateY(θ)` を適用すると局所 `+Z` 軸が `(+sin θ, +cos θ)` 方向へ回転する。
  - 4辺（左上・右上・左下・右下）の回転角を `[-angle, +angle, +angle, -angle]`（`angle = atan2(halfW, halfL)`）に設定することで、4本の白線が内向きに交差する `×` ではなく、頂点が閉じた中空ひし形（`◇`）を形成することを単体テストおよび実機画面で保証。
- **縦断区画線（中央線・車線境界線・路肩線）の横断歩道・導流帯クリッピング**:
  - `computeIncludedZSpans` / `isZRangeExcluded` により、横断歩道＋停止線領域（`crossZ ± 4.3m`）および中央導流帯領域（`[zebraCenterZ - 5.3m, crossZ + 4.3m]`）では黄色中央線・白破線・路肩白実線を自動的に分割・除外し、横断歩道やゼブラゾーンの上を縦線が突き抜けない構造を実現。
- **左側通行に準拠した片側停止線（Stop Line）**:
  - 横断歩道手前の停止線（幅 `0.45m`）は道路全幅を横断させず、進行方向の流入車線側のみ（`+Z` 進行の南側停止線は `x > 0` 側、`-Z` 進行の北側停止線は `x < 0` 側）に配置。
- **車線別 Z 軸占有スパン管理（`registerLaneSpan`）による重なりゼロ保証**:
  - 各車線ごとに配置済み標示の縦断占有区間 `[zCenter - halfSpanZ, zCenter + halfSpanZ]` を記録し、横断歩道から手前へ向かって **停止線（`-3.8m`）→ 進行方向矢印（`-9.5m`）→ 第1予告ダイヤ `◇`（`-18.0m`）→ 最高速度標示 `40`/`50`（`-26.5m`）→ 第2予告ダイヤ `◇`（`-35.0m`）** の順序で一切重ならずに整列配置。
  - 短〜中距離セグメント（`58m〜90m`）では第2横断歩道（`southCrosswalk`）を抑止し、十分な縦断長を持つ幹線道路セグメント（`length >= 120m`：渋谷・明治通り `164m`、東京駅・行幸通り `138m`）でのみ南側信号機と対になる横断歩道を生成。

## 7. 道路標識の透過境界アーティファクト排除・歩行者用信号機（警交仕規）の正対配置・横断歩道ガードレール開口部

実画面での視覚検証に基づき、道路標識・歩行者用信号機・横断歩道前ガードレールの3点について以下の改善を実施しています：

- **最高速度標識の旧実装統一と円形/異形標識の透過境界四角アーティファクト根絶**:
  - `RoadProps.createSpeedLimitSign` に残存していた旧3メッシュ実装（`z = 0` の高さ `3.8m` 支柱が看板表面・上端を突き抜け、数字部分に未照光 `MeshBasicMaterial` の `0.45m` 白四角 Plane を重ねていた問題）を廃止し、`JapaneseRoadSigns.createSpeedLimitSign` へ完全統一。
  - 円形・逆三角形・ひし形・五角形標識の `PlaneGeometry` 表面マテリアルすべてに `alphaTest: 0.5` を設定し、さらに `applyRoadSign3DTexture` / `applyRoadProp3DTexture` のフラグメントシェーダー冒頭で `if (diffuseColor.a < 0.5) discard;` を実行することで、透明四隅が深度バッファへ書き込まれてポストプロセスフォグや背景に対して「薄い黒い四角」として浮き出る現象を根絶。
- **日本の歩行者用信号機（LEDドットマトリクス式・赤立像/青緑歩行像）の向きとテクスチャ刷新**:
  - `createTrafficLight` 内の `PedestrianSignalHead` を支柱の横断歩道側（`z = +0.48`）へ配置し、`rotation.y = Math.PI / 2`（ローカル `+X` 方向＝車道を横断する対岸歩道向き）に90度回転させることで、横断歩道を渡る歩行者に正対する正しい向きへ修正。
  - 256×256 Canvas2D により、日本の薄型LED歩行者用灯器の太陽光防眩ルーバー・八角/円形マスク窓・LEDドットマトリクス素子配列（上段：帽子と肩幅のある赤色立像、下段：前傾で腕を振り歩幅を広げて歩く青緑色歩行像）および3面遮光フード（バイザー）を再現。
- **横断歩道前後のガードレール開口部（歩行者通路の確保）**:
  - `JapaneseRoadBuilder.buildProps` において、横断歩道が存在する位置（`crossZ = length * 0.25` および `southCrossZ = -length * 0.14`）の前後 `±4.2m`（計 `8.4m` 幅）およびセグメント端 `2.0m` をガードレール設置区間から除外し、複数の独立したガードレール区間（各自の両端に180度巻き込み袖ビーム付き）と分割物理コライダーを生成することで、歩道と横断歩道の間を歩行者が妨げなく通行できる構造を実現。

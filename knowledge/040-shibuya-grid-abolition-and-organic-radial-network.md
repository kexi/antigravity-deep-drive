# 渋谷エリア直角碁盤の目（格子グリッド）の完全廃止と実在有機的放射状曲線道路網への完全移行

## 1. 背景と課題

ユーザーからの「盤目廃止。道玄坂とか諸々よろしく。」という指示に基づき、渋谷エリアに初期の仮置きとして残存していた直角碁盤の目（格子状グリッド道路およびグリッド交差点）を完全に廃止し、実在する有機的な放射状曲線道路網（道玄坂、文化村通り、渋谷公園通り、井の頭通り・オルガン坂、玉川通り西進・首都高3号線直下、桜丘町さくら坂、円山町神泉仲通り、宮益坂）を完全な主軸道路網として再構成した。

### 解決前の問題点
1. **非実在の直角格子グリッド道路の残存**:
   - 明治通り（$x = -750$）を基準とする東西グリッド街路（$z = -200, -95, 95, 195$）、西通り（$x = -855$）、東通り（$x = -645$）およびそれらの直角交差点パッド（12箇所）が残存していた。
   - これらは京都や札幌のような碁盤の目であり、渋谷特有のスリバチ・谷底・丘陵地帯の実在の街路線形と激しく乖離していた。
2. **PLATEAU 実在建築物ポリゴンの不当なクリッピング切断**:
   - Blender 側の配置スクリプト（`generate_shibuya_plateau.py`）において、非実在グリッド線（$z = -95, -200, 195$、$x = -855, -645$）を保護するための道路クリアランス判定（Section F）が存在し、本来実在するはずの PLATEAU LOD2 建物群が直角の架空道路によって人工的に削り取られていた。
3. **車内ナビゲーション表示（`carModel.ts`）と 3D 道路メッシュの分断**:
   - 車内の大型カーナビ画面では直線の `getNavigationRoadCorridors()` のみを描画しており、せっかく構築した道玄坂や文化村通りなどのリアルな多頂点 Catmull-Rom スプライン曲線道路が車内ナビ画面に反映されていなかった。
4. **環状6号線（山手通り）と玉川通り（国道246号）西進の接続不良**:
   - 玉川通り西進が神泉町交差点（$x = -1250, z = 150$）で中途半端に途切れており、外側を走る山手通り（$x = -1350$）の交差点（旧 $z = 95$）と位置がずれて未接続だった。

## 2. 実装とアーキテクチャの変更

### 2.1 Web 側 3D 都市マップ（`tokyoStationMap.ts`）の刷新
- **非実在グリッド道路メッシュ・コライダーの完全撤去**:
  - `Route-246-Shibuya`（$z = 95$）、`Shibuya-Inaribashi-St`（$z = -95$）、`Shibuya-Namikibashi-St`（$z = -200$）、`Shibuya-Miyashita-Mitake-St`（$z = 195$）、`Shibuya-Sakuragaoka-West-St`（$x = -855$）、`Shibuya-Konnozaka-East-St`（$x = -645$）を全廃。
  - $x \in \{-855, -750, -645\} \times z \in \{-200, -95, 95, 195\}$ の全12箇所の直角交差点パッドおよび路面標示を完全削除。
- **明治通りの一本化・最適化**:
  - 碁盤の目によって細切れに分割されていた明治通り渋谷区間（$x = -750$）を、恵比寿北端（$z = -210$）から宮益坂下南（$z = 236$）まで全長 446m の連続した美しい 3車線大通り（`Meiji-dori-Shibuya`）として統合。
- **山手通り・神泉町交差点の整合**:
  - 環状6号線（山手通り）の南北セグメントを $z = 150$ で交差するよう分割・調整し、玉川通り西進と直交接続する交差点パッド `{ x: -1350, z: 150, w: 32, d: 28, lx: 3, lz: 2 }` を新設。

### 2.2 オープンデータ・ナビゲーション定義（`gsiPlateauLoader.ts`）の整備
- **非実在グリッドコリドー・交差点の削除と放射状幹線セグメント登録**:
  - `SHIBUYA_GSI_ROAD_SEGMENTS` から架空グリッド線（稲荷橋、並木橋、美竹、桜丘西、金王坂東）を完全全廃し、実在の道玄坂・文化村通り・渋谷公園通り・井の頭通り・玉川通り西進・さくら坂・円山町神泉仲通り・宮益坂・神南二丁目連絡路の9大実在路線を正式登録。
  - `NAVIGATION_ROAD_CORRIDORS` に上記 9 本の放射状曲線道路コリドーを直接統合し、`carModel.ts` 側で行われていた不要な結合・重複排除ハックを解消。
  - `NAVIGATION_INTERSECTIONS` から架空交差点（稲荷橋、並木橋、宮下公園前、フクラス西、桜丘西口、金王坂上、ストリーム東）を全削除し、実在する「宮益坂下（$x = -750, z = 248$）」「SHIBUYA109前（$x = -830, z = 252$）」「セルリアンタワー前（$x = -855, z = 95$）」「青山通り・表参道方面接続（$x = -400, z = 248$）」を登録。
  - `nav-int-yamate-shinsen` を玉川通り合流点である $z = 150$ に更新。
- **建物スペック座標の幾何学的一貫性修正**:
  - `13113-bldg-qfront-109`: 渋谷スクランブル交差点直上（$z = 248$）にダミー配置されていた座標を、実在のスクランブル交差点北側（$x = -818, z = 285$、幅・奥行き $32\text{m}$）に修正。
  - `13113-bldg-miyashita-park`: 宮益坂車道直上（$z = 248$）に仮置きされていた座標を、明治通り沿道（$x = -695, z = 320$）の実在位置へ是正。

### 2.3 車載カーナビ描画（`carModel.ts`）と 3D 道路交差点パッド
- `renderCarNavigationDisplay` を `getNavigationRoadCorridors()` 単一ソースに一本化し、車載マルチメディア画面に道玄坂の滑らかなカーブや 109前のY字分岐、神泉町〜山手通りの延伸線が精細にリアルタイムレンダリングされるよう整理。
- `tokyoStationMap.ts` の `shibuyaRadialIntersections` にセルリアンタワー前（$x = -855, z = 95$）および渋谷駅東口（$x = -750, z = 95$）の交差点フラットアスファルトパッドを追加し、玉川通り・さくら坂・明治通り・国道246号の接続端点が宙に浮く現象を防止。

### 2.4 Blender スクリプト（`generate_shibuya_plateau.py`）の建物クリアランス整合
- **非実在グリッド判定（Section F）の完全撤去**:
  - 架空グリッド $z = -95, -200, 195$ および $x = -855, -645$ のクリッピングロジックを全削除。
- **実在道路ポリライン・交差点クリアランスへの集約**:
  - `ROAD_CORRIDOR_POLYLINES` の `Tamagawa_West` を $(-1350.0, 150.0)$ まで延伸、`Sakurazaka` 始点を $(-855.0, 95.0)$ に接続、`Jinnan_Cross` を $(-855.0, 440.0)$ まで延伸。
  - `ROAD_INTERSECTION_CLEARANCES` に山手通り交差点 $((-1350.0, 150.0), 22.0)$、セルリアンタワー前 $((-855.0, 95.0), 22.0)$、渋谷駅東口 $((-750.0, 95.0), 22.0)$ を追加。
  - 東側国道246号青山通り区間の判定範囲を実在区間（$-735.0 \le x \le -260.0$）に限定。

## 3. 検証とテスト

   - 廃止された非実在グリッド道路（6件）および交差点（7件）が完全に存在しないことをアサート。
   - 実在放射状曲線道路（9件）がすべて定義され、4点以上の滑らかなポリラインで構成されていることを検証。
   - 玉川通り西進および山手神泉交差点が $(-1350, 150)$ で正確に整合していることを検証。

# 全ウィンドウガラス（フロント・6ライトサイド・リア）の3D曲面モデリングと雨滴光学屈折・走行速度別空力ストリークシェーダー

## 概要

運転席コックピット視点（および左右振り向き・後方確認時）とチェイス視点でのリアルなドライブ体験を実現するため、フロントガラス（`Windshield`）だけでなく、トヨタ クラウン セダン（AZSH32）特有の **左右6ライトサイドガラス（`SideWindows`：フロントドア窓・リアドア窓・6ライトリアクォーター窓）** および **ファストバックリアガラス（`RearWindow`）** を Blender 3D 曲面メッシュ＋プロシージャル光学雨滴・走行風空力ストリークシェーダーとして統合実装した。

## 過去に発生した不具合と根本原因の訂正

初期実装では「3D ワイパーの向きや位置が不自然」「雨粒が不自然でワイパーで拭けていない」「フロント以外にサイドガラスがなく、リアガラスも雨滴非対応の低ポリゴン面だった」「加減速時に雨粒がワープし、高速走行でも雨粒が風で吹き上がらない」という問題が発生していた。調査・計測により特定した根本原因と解決策は以下の通り：

1. **glTF 2.0 仕様の V 座標反転による上下逆転**:
   - Blender で `v = (z - min_z) / range_z` として出力した UV が、glTF エクスポータの `1.0 - v` 変換によって Three.js 読み込み時に `vUv.y = 0.0` が上端ルーフ側、`vUv.y = 1.0` が下端カウル側に反転していた。そのためシェーダーのワイパー支点がルーフ上端に配置され、雨粒の落下方向も逆転していた。
   - **対策**: `CarModel.normalizeWindshieldGeometryUVs()` および `generate_vehicle_model.py` の双方で、運転席右端 (`x = -0.74`) を `u = 0.0`、助手席左端 (`x = +0.74`) を `u = 1.0`、下端カウル (`y = 0.88`) を `v = 0.0`、上端ルーフ (`y = 1.42`) を `v = 1.0` に厳密正規化した。
2. **3D ワイパーメッシュとシェーダー払拭領域の座標・傾斜角不一致**:
   - 旧 3D ワイパーは傾斜角 `-0.68 rad`（実際のガラス面は `-0.977 rad = -56.0°`）でガラス前方の空中に浮き、初期角度 `rotation.z = 0.2` でガラス中央に縦に突っ立っていた。
   - **対策**: 3D ワイパーをガラス傾斜角 `-0.977 rad` に密着させ、右ハンドル日本車仕様のピボット位置（運転席 `(-0.58, 0.891, 1.275)` = シェーダー `(0.16m, 0.02m)`、助手席 `(0.06, 0.891, 1.318)` = シェーダー `(0.80m, 0.02m)`）とブレード払拭半径（運転席 `[0.08m, 0.86m]`、助手席 `[0.08m, 0.66m]`）、掃引角度（下端パーク `0.08 rad` 〜 最大角 `1.62 rad` / `1.56 rad`）を 3D メッシュと GLSL シェーダーで完全一致させた。
3. **ワイパー通過履歴 (`strokeAge`) の欠如**:
   - 旧シェーダーは現在角度の前後 `0.18 rad` のみをクリアしていたため、ブレードが通り過ぎた瞬間に雨粒が 100% 再出現していた。
   - **対策**: 往復ストローク方向 `uWiperDir` (`+1.0`: 往路 / `-1.0`: 復路) と現在角度から、各ピクセルがブレード通過後にどれだけ経過したか (`strokeAge`) を算出し、通過直後は 100% 消去、時間経過とともに新しい雨滴が1粒ずつランダムに着水・成長する物理サイクルを実装した。
4. **水滴計算関数の `effectiveRain` 未連動とガラス全面の一様な白濁**:
   - 両関数に局所残存雨量 `effectiveRain` を渡し、水滴以外の素ガラス面はクリアなフレネル透過 (`alpha = 0.04..0.22`) に保ちつつ、水滴内部は球冠法線による上下反転レンズ屈折・メニスカス全反射リム・ピンポイントハイライトで描画するよう刷新した。
5. **左右6ライトサイドガラス (`SideWindows`) とリアガラス (`RearWindow`) のモデリングおよびガラス種別シェーダー (`uGlassType`)**:
   - 旧モデルでは左右のドア窓〜クォーター窓が空洞であり、さらに車内 `Interior` の Aピラーアルカンターラ内張りが `y = -0.82 .. -0.24`（外装 Aピラーより約 `0.4m` 後方）に配置されてフロントドア窓の視界を横切っていた。
   - **対策**:
     - `blender/scripts/generate_vehicle_model.py` で車内 Aピラー内張りを外装 Aピラー内面（`y = -1.22 .. -0.48`）へ正確に一致させ、Aピラー〜Bピラー〜6ライトディバイダー〜ファストバックCピラーに隙間なく密着するタンブルホーム曲面 `SideWindows` メッシュ（左右計6パネル）と、16×12 高分割3D曲面 `RearWindow` メッシュを独立生成した。
     - `apps/web/src/shaders/windshield.ts` に `uGlassType`（`0.0`: フロントガラス、`1.0`: サイドガラス、`2.0`: リアガラス）を導入し、サイドガラスではワイパー払拭を無効化して走行風で車両前方 (`u=0`) から後方 (`u=1`) へ斜め下方に流れる雨滴ストリークと JDM グリーン UV カットティントを描画、リアガラスではプライバシースモークティントと水平14本の銅色熱線デフォッガー（ヒータープリント線＋左右バスバー）およびスロープ滑落雨滴を描画した。
6. **`uTime * speedFactor` による加減速時の雨粒ワープと、走行速度に応じた空力吹き上がり・ストリーク変形の実装**:
   - 旧実装は `scrolledY = warpedP.y * scale.y + time * fallRate(speedFactor) * 2.2` のように総経過時間 `uTime` と瞬間速度係数の積でスクロール位置を決めていたため、加速・減速した瞬間に `uTime` の大きさに比例して雨粒が数十セル単位でワープ（逆再生スクラブ）していた。また `gravityVsWind = 1.0 - speedFactor * 0.65` が常に正（`>= +0.35`）だったため、100 km/h 以上でも雨粒が下へ落ち続け、雨粒やトレイルの向きも真下固定だった。
   - **対策**:
     - **時間積分位相ユニフォーム (`uWindScrollY`, `uWindScrollX`) と `computeGlassRainScrollRates()`**: `CarModel.update(dt, state, rainIntensity)` で毎フレーム `dt` に応じて縦・横の気流スクロール角速度を積分することで、急加速・急減速でも雨粒がワープせず滑らかに加速・停滞・反転するように改善した。
     - **走行速度3段階レジームと局所気流ベクトル配向 (`computeLocalAirflowVector`)**:
       - **停車〜低速域 (`0 – 35 km/h`)**: 重力が支配し (`scrollYRate > 0`)、表面張力で蛇行しながらカウル下端 (`-Y`) へ滑落。
       - **中速・気流均衡域 (`35 – 60 km/h`)**: 34°傾斜ガラスの風圧揚力と重力が拮抗 (`scrollYRate ≈ 0`)。水滴は気流剥離による高周波の微振動 (`windTremor`) で震えながら左右 A ピラー方向へ放射状にドリフトし始める。
       - **高速走行域 (`65 – 140+ km/h`)**: 動圧（$\propto v^2$）が重力を振り切り (`scrollYRate < 0`)、雨粒がルーフ上端 (`+Y`) かつ左右 A ピラー外側 (`radialX`) へ放射状に吹き上がる。局所気流ベクトル `flowDir` に沿った 2D 回転座標系 (`wakeDir`, `crossDir`) により、着水雨滴の空力ティアドロップ変形 (`aeroStretch`) と滑走水滴の連続ウォーターストリーク＆後流マイクロビーズが気流方向へ正確に伸びる。さらに高速域ではワイパー掃引域内にも着水直後の風圧ストリークが走り（ブレード接触直下 `bladeContactMask` は 100% 払拭）、コックピット視点でのスピード感を大幅に強化した。
